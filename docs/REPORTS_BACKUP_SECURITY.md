# Reports, backup and local security

## Offline reports

The More tab exports nine CSV reports through Android's Storage Access Framework:
portfolio summary, holdings, transactions, cash contributions, dividend income,
performance, allocation versus benchmark, latest rebalance plan, and annual wealth
summary. The owner chooses every destination. Reports make unknown values blank and
protect free-text cells from spreadsheet formula injection.

## Versioned backup

Backups are ZIP files containing `manifest.json` and `backup.json`. The manifest
identifies format version 1, Room schema 2, backup kind, creation timestamp, and
record counts. Essential backups contain portfolios, securities, transactions,
targets, watchlists/notes, dated fundamentals, index definitions, and saved plans.
Full backups additionally include quotes, daily prices, and index snapshots.

Before a restore, the app enforces size limits and validates:

- exact entry names, format version, schema and manifest counts;
- duplicate primary/composite keys;
- portfolio, watchlist, plan and index-snapshot references;
- transaction types, dates, symbols, finite numbers, target ranges and positive
  cached market prices.

The UI shows counts and warnings before confirmation. Confirmed replacement clears
and inserts related tables in one Room transaction, so validation failure or an
insert failure cannot leave a partially restored ledger. Security preferences are
deliberately excluded so a backup cannot enable or replace a device PIN.

## Local security

Security is optional and network independent. A 4–8 digit PIN is verified with
HMAC-SHA256 using a non-exportable key generated by Android Keystore; the PIN and
key are never stored in the database or backup. Device authentication uses AndroidX
BiometricPrompt with strong biometric or the device credential. Configurable
inactivity locking is process-local, and screen privacy uses Android `FLAG_SECURE`.
No custom encryption algorithm is used.

Android application data should still be protected with a device passcode and
normal OS storage encryption. Losing both the device security key and access to the
app can make a configured PIN verifier unrecoverable; maintain an essential backup.

## Diagnostics and preferences

Provider capability rows expose last attempt, last success, cached record count,
and sanitized last error. Failed refreshes preserve the prior cache. Settings for
theme, Standard versus Lakh/Crore display, default portfolio/benchmark/rebalance
inputs, optional refresh scheduling, privacy, and locking persist in DataStore.
